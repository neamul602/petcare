# 3.3 · Spec — Incoming Booking Request

> Full pet profile + care config upfront. Rashid confirms or declines without WhatsApp back-and-forth. The structural answer to Rashid Want #2 (care-record credit on profile) and the gate to Scenario 04's acute-event runbook.

## URL & Routing

- **Route:** `/provider/requests/:requestId` · SSR for desktop, SPA-hydrated mobile
- **Polling:** countdown ticks every second client-side · silent (no server poll needed)
- **Capture-on-confirmation:** Accept tap charges Bibi's authorization hold immediately (Brief §3 explicit: capture-on-confirmation, not capture-on-completion)

## Design Sections

**D1. Header** — request ID · back to dashboard · preserves request in pending state

**D2. Countdown banner** — `{info-soft}` · live MM:SS · color shifts to warning at <1h · shifts to destructive at <15m

**D3. Owner card** — `{card.muted}` · avatar + name + verified badge · past-stay count if any · "1 stay · 5★ verified review" if repeat owner

**D4. Pet card** — `{card.muted}` · thumbnail + identity block · medical flag inline (Diabetes chip · `{badge.warning-soft}`)

**D5. Care config block** — `{card.elevated}` · the critical section
- Each care-config row: icon + label + value
- Insulin line includes timing + storage
- Diet line includes restrictions
- Anxiety triggers surfaced prominently (icon + descriptive)
- Special instructions: free-text quoted, max 280 chars displayed
- Vet contact: phone-pickable link

**D6. Stay + price block** — `{card.muted}` · dates + nights · "Authorization hold" copy (not "charge")

**D7. Sticky Action Bar** — `{sticky-action-bar}` · Decline (secondary) + Accept (primary) · Cancel-equivalent via Decline opens structured-reason modal (3.4)

## On-Page State Machine

- **State 1 (default — fresh request):** All sections visible · countdown running · CTAs enabled
- **State 2 (repeat-owner):** Past-stay badge prominent · "You've hosted Tito before · 5★" · `{success-soft}` background on owner card
- **State 3 (new owner):** Standard card · "First-time booking" tag · no past-stay indicator
- **State 4 (special-care-heavy):** Banner "This booking requires insulin administration · confirm medication capability" · `{warning-soft}`
- **State 5 (capacity-tight):** Banner "1 spot remaining for this date" · inline above care-config
- **State 6 (countdown <1h):** Banner shifts `{warning-soft}` · countdown color orange
- **State 7 (countdown <15m):** Banner shifts `{destructive-soft}` · countdown color red
- **State 8 (countdown expired):** Request auto-released to next provider · page shows "This request was released · expired" · CTAs disabled

## Accessibility

- Countdown: `role="timer" aria-live="off"` · `aria-label="4 hours 32 minutes remaining to confirm"`
- Care-config block: `<section aria-labelledby="care-config-h">` with semantic list inside
- Vet contact: `<a href="tel:+880-...">` · single-tap on mobile · `aria-label="Call Dr. {Name} at {clinic}"`
- Special-care banner: `role="status" aria-live="polite"` announces capability requirement
- Capacity-tight banner: `role="status"` announces remaining count
- Repeat-owner / first-time tag: `aria-label` provides full context, not just visual
- Accept/Decline CTAs: `aria-label` includes pet name + dates · focus ring always visible
- Expired state: `role="alert"` announces release
- All CTAs ≥48px tap target

## What This Page Must NOT Do

- No counter-offers (Brief §6: accept-or-decline only in v1)
- No price negotiation
- No "discuss with owner first" chat before deciding (care config is sufficient)
- No auto-accept (every decision is Rashid's)
- No counter-numbers on capacity ("accept this and lose a spot you could fill later")
