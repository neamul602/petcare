# 3.7 · Spec — Booking Completion (Provider Marks Complete)

> Close the stay, trigger the payout release, prompt Bibi for a verified review. The natural end of the daily-update loop and the gate to Rashid's demonstrated-Fit deepening.

## URL & Routing

- **Route:** `/provider/bookings/:bookingId/complete` · accessible from 3.5 (in-stay management) when stay end-date passes
- **Eligibility gate:** backend returns 403 if `booking.end_date > today` (can't complete future-dated stay)
- **Side effects:** payout release queued · verified-review prompt pushed to Bibi · care history updated · Fit delta calculated

## Design Sections

**D1. Header** — back to 3.5 · "Mark complete" · stays focused on the action

**D2. Booking summary card** — `{card.muted}` · pet + dates + nights + gross/net amount

**D3. Stay metrics block** — `{card.muted}` · daily-updates count · acute events · verified-review status

**D4. Side-effects preview** — `{card.elevated}` · bullet list of what happens on confirm
- Payout release queued with amount
- Verified-review prompt pushed
- Care history archived
- Fit delta projected (e.g., "+1 diabetic small dogs handled")

**D5. Missed-update warning** (conditional) — `{warning-soft}` · only shown if any daily updates were missed · soft tone, no penalty

**D6. Sticky Action Bar** — `{sticky-action-bar}` · Mark stay complete (primary, size.lg) + Cancel (link) returning to 3.5

## On-Page State Machine

- **State 1 (default — eligible, all updates posted):** All sections visible · green check on metrics · Mark complete enabled
- **State 2 (eligible, missed updates):** Missed-update warning visible · soft tone · Mark complete still enabled
- **State 3 (acute-event still active):** Cannot complete · inline message "Acute event active · close runbook first" · Mark complete disabled
- **State 4 (dispute-window-open):** Completion allowed · payout on hold pending Admin review · side-effects preview shows "Payout on hold" instead of "Payout release queued"
- **State 5 (not yet end-date):** Page inaccessible · backend returns 403 · redirects to 3.5
- **State 6 (confirm-success):** Routes to 3.1 with toast · booking moves to Completed column · payout row appears in 3.10

## Accessibility

- Booking summary: `<section aria-labelledby="summary-h">`
- Stay metrics: `<dl>` semantic · each metric is `<dt>`/`<dd>`
- Side-effects preview: `<ul>` with check-glyph list items · `aria-label="What happens on confirm"`
- Missed-update warning: `role="status"` · soft tone, not `role="alert"`
- Acute-event-blocked: `role="alert"` announces blocking condition
- Mark complete CTA: `aria-disabled="true"` when blocked · `aria-describedby` explains why
- Confirm-success: live region announces toast + state changes
- All CTAs ≥48px tap target

## What This Page Must NOT Do

- No blocking completion for missed updates (soft expectation, not penalty)
- No forcing verified review submission before completion (review is Bibi's choice)
- No holding payout beyond dispute window (capture-on-confirmation already happened)
- No upselling on completion ("Want to add grooming next time?")
- No pressure CTAs ("Mark complete now to release payout faster")
