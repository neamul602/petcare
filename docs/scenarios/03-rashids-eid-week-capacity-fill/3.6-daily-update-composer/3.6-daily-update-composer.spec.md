# 3.6 · Spec — Daily Update Composer

> Photo + structured note in under 60 seconds. The update accumulates into Care History and into Rashid's demonstrated-Fit profile. **The composition surface — where care-records accumulate into the trust signal.**

## URL & Routing

- **Route:** `/provider/bookings/:bookingId/updates/new` · modal-pattern (slides up from 3.5)
- **Image upload:** presigned S3 / equivalent · max 5MB per photo · 1-4 photos
- **Voice input:** Web Speech API · Bangla + English · browser-dependent fallback to typing

## Design Sections

**D1. Header** — back to 3.5 · "Post daily update" · day-of-stay context strip

**D2. Photo upload zone** — 4 slots · first slot is "+" affordance · tap opens camera or gallery · each photo shows thumbnail + remove (×) on tap-and-hold · caption per photo (optional)

**D3. Care log section** — `{card.muted}` · structured fields
- **Insulin:** radio (Given / Skipped / Partial) + time input · given is default
- **Kibble portion:** free-text · auto-suggest from past updates (no auto-fill, just suggestions)
- **Behaviour:** multi-toggle (Calm / Active / Anxious)
- **Any concerns:** None checkbox + free-text · voice-input mic icon

**D4. Glucose observation** — radio (Normal / Slight drop / Slight rise / Concerning)
- When "Concerning" selected, inline helper: "See acute-event runbook · you can still post this update"

**D5. Preview toggle** — collapsible section · shows what Bibi will see in her in-stay view

**D6. Helper line** — `text-xs text-muted-foreground` · "Takes 30 sec · helps Bibi stay informed · builds your demonstrated-Fit"

**D7. Sticky Action Bar** — `{sticky-action-bar}` · Post update (primary, size.lg) + Save as draft (link) · CTA disabled until ≥1 photo uploaded

## On-Page State Machine

- **State 1 (default — empty form):** All fields empty · photo slots empty · CTA disabled
- **State 2 (photo-required):** CTA disabled until ≥1 photo uploaded · helper shows "Photo required"
- **State 3 (insulin-given):** Time input visible · default to 8am · time picker open
- **State 4 (insulin-skipped):** Time input hidden · kibble portion becomes required (no insulin given = monitoring needed)
- **State 5 (any-concerns-checked):** Free-text becomes required · voice mic enabled
- **State 6 (concerning-glucose-flagged):** Inline helper shows "See acute-event runbook" link — hard-links to Scenario 04 admin runbook at [`../../04-ayaats-eid-week-runbook-execution/4.2-acute-event-runbook/4.2-acute-event-runbook.spec.md`](../../04-ayaats-eid-week-runbook-execution/4.2-acute-event-runbook/4.2-acute-event-runbook.spec.md) (R-10 launch-blocking) · CTA still enabled (post is informational, not blocking)
- **State 7 (preview-open):** Preview section expanded · shows Bibi's view of the update
- **State 8 (submit-success):** Routes to 3.5 with toast · new update at top of past-updates list

## Accessibility

- Header: `<header>` semantic · day count `aria-label="Day 4 of 9, today"`
- Photo zone: `<button>` per slot · `aria-label="Add photo {N} of 4"`
- Care log: `<fieldset>` per field group · `<legend>` for each
- Insulin radio: arrow-key navigable · time input is `<input type="time">`
- Behaviour toggles: `role="checkbox" aria-checked` per chip · multi-select pattern
- Glucose radio: "Concerning" selection triggers `role="status" aria-live="polite"` helper
- Voice mic: `aria-label="Voice input"` · `aria-pressed` reflects recording state · visual pulse while listening
- Preview: `<details>` native · expanded state preserved across re-renders
- Post CTA: disabled until valid · `aria-describedby` explains why (photo required)
- All CTAs ≥48px tap target

## What This Page Must NOT Do

- No auto-fill from past updates (authenticity matters)
- No scheduling updates in advance (soft-enforcement only works if updates are real-time)
- No forcing structured fields beyond photo + behaviour tag (rest is optional)
- No penalty for skipping (it's a soft expectation)
- No "Concerning glucose" auto-triggering acute-event runbook (helper link only — Rashid decides)
