# 3.4 · Spec — Booking Confirmation Decision

> The structural gate. Accept or decline, with structured decline reasons that feed the routing-data layer. **Brief §3 taxonomy is first-class** — every decline becomes algorithm-training data.

## URL & Routing

- **Route:** `/provider/requests/:requestId/decision` · modal-pattern, not standalone page
- **Modal entry:** Accept tap on 3.3 → confirmation modal · Decline tap → structured-reason modal
- **Capture-on-confirmation:** Accept fires immediately, optimistic UI updates booking state to `{booking-state.captured}` in 3.1

## Design Sections

**D1. Modal shell** — `{card.elevated}` · centered · max-width on desktop · bottom-sheet on mobile · focus-trapped · Escape closes (returns to 3.3)

**D2. Accept modal contents**
- Header: "Accept {pet}'s stay?"
- Summary card: pet + dates + price + care flag (Insulin BID)
- Helper: "Capture-on-confirmation: Bibi's payment will be charged" · `{info-soft}` callout
- Cancel + Accept CTAs · Accept is `{button.primary, size.lg}`

**D3. Decline modal contents**
- Header: "Decline {pet}'s stay"
- Reason taxonomy: 6 radio options (Brief §3 explicit) — exactly one required
- Optional free-text elaboration · 280 char max
- Cancel + Submit decline CTAs · Submit disabled until reason selected

**D4. After-action states**
- Accept success: routes to 3.1 with booking in Confirmed column · toast: "Tito's booking confirmed · Bibi notified"
- Decline success: routes to 3.1 with request removed · toast: "Decline logged · Ayaat notified for monitoring"

## On-Page State Machine

- **State 1 (Accept modal — default):** Summary shown · helper visible · both CTAs enabled
- **State 2 (Accept success):** Optimistic UI · modal closes · routes to 3.1 · booking moves to Confirmed · toast
- **State 3 (Decline modal — default):** Reasons visible · no selection · Submit disabled
- **State 4 (Decline modal — reason selected):** Free-text enabled · Submit enabled
- **State 5 (Decline modal — generic-decline selected):** Free-text required · char count shown · Submit disabled until ≥10 chars
- **State 6 (Decline success):** Modal closes · routes to 3.1 · request removed · toast

## Accessibility

- Modal: native `<dialog>` element · focus trap · Escape closes · `aria-labelledby` connects to header
- Accept modal: confirmation pattern · Enter triggers Accept
- Decline reasons: `<fieldset>` + `<legend>` semantic · radio group navigable with arrow keys
- Free-text elaboration: `aria-describedby` linking to char count
- Submit-decline disabled state: `aria-disabled="true"` · `aria-describedby` explains why
- Generic-decline required text: `aria-required="true"` · live char count
- After-action: live region announces toast
- All buttons ≥48px tap target

## What This Page Must NOT Do

- No counter-offers (Brief §6 explicit: accept-or-decline only in v1)
- No price negotiation
- No "discuss with owner first" chat before deciding
- No skipping decline reason (taxonomy enforced — Brief §3)
- No decline-without-elaboration for "Generic decline" reason (free-text required)
- No batch decline (each request is a discrete decision)
