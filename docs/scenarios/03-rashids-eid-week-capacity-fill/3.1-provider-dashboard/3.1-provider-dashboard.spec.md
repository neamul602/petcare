# 3.1 · Spec — Provider Dashboard (Bookings + Capacity)

> Rashid's Eid-week command center. Pending requests, confirmed bookings, in-stay management, capacity bar, payouts, and care-record stats — all on one screen because Eid-week doesn't tolerate navigation friction.

## URL & Routing

- **Route:** `/provider/dashboard` · SSR · deep-linkable
- **Auth gate:** `provider` role required · redirects to `/provider/sign-in` if missing
- **Polling:** every 30s for pending-request count + capacity changes (NFR-15)
- **Push:** subscribe to `provider.{id}.requests` and `provider.{id}.bookings` channels · unsubscribe on unmount

## Design Sections

**D1. Header** — provider name + `{tier-a-badge}` · gear icon → settings · expand icon → opens desktop full-screen

**D2. Quick-stats strip** — `tabular text-sm` · 4 stats in a row · dot-separated on mobile · 4-column on desktop · includes Eid-week utilization as the headline

**D3. Peak-window banner** — `{accent-soft}` background · only shows during active peak (Eid-week, December, summer) · explains expanded capacity and peak terms

**D4. Tab bar** — 4 tabs: Today (default) · Calendar (→ 3.2) · Payouts (→ 3.10) · Profile (→ 3.8) · active tab underlined in primary

**D5. Pending requests list** — `{provider-card.standard}` reused for each request · care-config tags inline · countdown timer · Confirm/Decline CTAs inline
- Sorted by submission time (oldest first — first-come-first-served fairness)
- Empty state: "No pending requests — check back soon" with `text-muted-foreground`

**D6. In-stay bookings list** — same card variant · additional `✓ Update posted today / ⏳ Due today` status badge

**D7. Capacity bar (mini)** — visual per-day · cells use `{capacity-cell.*}` tokens · peak-window dates show `peak` style

**D8. Care-record footer** — single stat line · the demonstrated-Fit headline number · `+1` delta badge when Fit climbed this session

## On-Page State Machine

- **State 1 (default — Eid-week peak active):** Peak banner visible · pending list populated · in-stay card visible · capacity at 95% · care-record footer showing latest Fit
- **State 2 (quiet/off-peak week):** Banner swaps to "Off-peak · consider running a re-engagement nudge" · pending list may be empty · capacity bar shows under-utilization · admin can suggest nudge copy
- **State 3 (acute event active):** Banner replaces peak/quiet banner with "1 acute event active · Open Runbook" · banner styled `{destructive-soft}` · CTA primary routing to acute-event surface
- **State 4 (capacity near full):** Inline banner above pending list: "3 of 5 spots filled for tomorrow's window" · `{warning-soft}`
- **State 5 (no pending requests):** Pending section shows empty state · in-stay list takes full visual weight
- **State 6 (Tier-A first-time-setup):** Provider onboarding banner: "Welcome to Tier-A · here's what changes" · links to admin support

## Accessibility

- Header: `<header>` semantic · Tier-A badge `aria-label="Tier-A provider, admin-vetted"`
- Quick-stats strip: `<dl>` semantic · each stat is `<dt>`/`<dd>`
- Tab bar: `role="tablist"` · each tab `role="tab" aria-selected` · arrow-key navigation
- Pending cards: `<article>` semantic · Countdown `aria-live="off"` (silent, not chatty)
- Capacity bar: `<ul>` with each day as `<li>` · cell tooltip on focus
- Care-record footer: `role="status" aria-live="polite"` if Fit climbed this session
- All interactive elements ≥48px tap target · spacing respects 8-grid baseline
- Bengali content uses `lang="bn"` when applicable · mixed EN+BN follows longest-content rule

## What This Page Must NOT Do

- No on/off toggle for capacity (Brief §6: date-level capacity, not toggle)
- No auto-adjust based on bookings (Rashid's intentional setting is the source of truth)
- No blocking stay completion on missed updates (within linked pages)
- No gamification of Fit numbers (Fit is informational, not a leaderboard)
- No provider comparison ("Rashid ranks #3 in Gulshan") — Tier-A is the ceiling
