# 1.6 — Booking Configuration

## Page Metadata

| Property | Value |
|---|---|
| **Scenario** | 01 — Bibi's First Eid Booking with Tito |
| **Page Number** | 1.6 |
| **Platform** | Mobile (PWA, mid-range Android) |

## Overview

**Page Purpose:** Configure the stay-specific care needs (food for THIS stay, additional services for THIS stay, free-text instructions) so the provider confirms with full information — no WhatsApp back-and-forth needed.

**Entry Context:** Bibi just saved Tito's profile on 1.5. This page is pre-populated with Tito's saved defaults (low-carb kibble, insulin BID, anxiety triggers) but exposes stay-specific overrides.

**Exit Action:** Tap **"Review & submit booking request"** → next page (1.7 — Booking Submission + Payment Authorization).

**On-Page Interactions:**
- Date picker (pre-filled with Eid-1 → Eid+9; editable)
- Toggle "Use Tito's saved food type" — defaults ON, toggle OFF to override for this stay
- Toggle additional services (extra walk · extra attention · basic medication administration)
- Free-text instructions box (1000 char)
- Tap "Review & submit" — primary CTA, sticky

## State Variations

| State | Trigger | Behavior |
|---|---|---|
| **Default pre-filled** | Page load (first booking) | All defaults from Tito's profile · services unchecked |
| **Capacity-conflict** | Provider's capacity changed since 1.4 | Banner: "Rashid's availability has changed — please adjust dates or choose another provider" · CTA disabled |
| **Date-edited** | User changes dates | Re-query capacity · "Available for new dates ✓" or warning |
| **Free-text-counter** | User types over 800 chars | Counter turns orange · over 1000 → counter turns red · save disabled |
| **Returning-user + Scenario 02 path** | Booking again | Pre-fill from Tito's last care history + this provider's last config — but Scenario 02's "Book again" path is a *separate* route through the dashboard that bypasses most of this form. This page is still the stay-specific step. |

---

## What This Page Must NOT Do

- **No re-asking what Tito's profile already captured** — pre-fill from profile; stay-specific overrides only
- **No "contact provider for custom requests" workaround** — the structured form must capture it (this is what eliminates WhatsApp back-and-forth)
- **No upsells beyond what the provider offers** — additional services are pulled from the provider's published service list
- **No price changes after confirmation** — what Bibi sees here is what she pays
