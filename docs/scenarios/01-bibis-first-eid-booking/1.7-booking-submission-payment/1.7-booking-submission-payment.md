## Overview

**Page Purpose:** Show Bibi a final review of her booking request + authorize the payment hold (no capture yet) — this is the *commit moment* where the first-care-history seed lands on the platform.

**Entry Context:** Bibi tapped "Review & submit booking request" on 1.6. This page is a final-review screen with the payment-authorization step at the bottom.

**Exit Action:** Tap **"Submit booking request"** → next page (1.8 — Booking Confirmation State).

**On-Page Interactions:**
- Tap "Edit" on any section — returns to 1.6 with that section focused
- Tap payment-method selector — modal opens (bKash / Nagad / Card)
- Tap "Submit booking request" — primary CTA · triggers authorization hold + submission
- Tap "Save as draft" — secondary

## State Variations

| State | Trigger | Behavior |
|---|---|---|
| **Default review** | Page load | Summary visible · payment method pre-selected · CTA enabled |
| **Submitting** | Tap Submit | Loading state on CTA · payment gateway call · typically 5–15s |
| **Authorization-success** | Gateway confirms hold | → next page (1.8) |
| **Authorization-fail** | Gateway declines | Inline error · "Try another payment method" · CTA re-enabled |
| **Gateway-timeout** | 30s no response | "Connection slow — try again or save as draft" · CTA re-enabled |
| **Save-as-draft** | Tap secondary | Returns to Owner dashboard with draft visible |

---

## What This Page Must NOT Do

- **No "Book now!" pressure language** — brand-voice discipline (TM Handover open item #5)
- **No hidden fees** — the brief is explicit: cost opacity is one of the things that breaks the current informal supply (Brief §1)
- **No capture-at-submission** — capture happens on provider confirmation, not request (Brief §3 payment-timing note)
- **No subscription / auto-renew / saved-card-default** — single-booking authorization
- **No urgency-bait** — no "Provider may decline if you wait!"; Rashid's typical confirmation time is informational, not coercive

## On-Page State Machine (Storyboard)
