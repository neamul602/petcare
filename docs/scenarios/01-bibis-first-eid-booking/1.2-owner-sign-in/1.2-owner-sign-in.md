# 1.2 — Owner Sign-In (Phone OTP)

## Page Metadata

| Property | Value |
|---|---|
| **Scenario** | 01 — Bibi's First Eid Booking with Tito |
| **Page Number** | 1.2 |
| **Platform** | Mobile (PWA, mid-range Android) |

## Overview

**Page Purpose:** Verify Bibi's phone so the booking record has a real identity attached (Brief §6 platform-is-not-anonymous), capture her default neighborhood for the shortlist filter, and route her to the curated shortlist in under 60 seconds.

**Entry Context:** Bibi just tapped "Find care near me" from the landing page. Browser permission for location was either granted (location pre-filled) or denied (manual picker open). The page is a single-screen OTP flow — no scroll needed on a mid-range Android.

**Exit Action:** Tap **"See providers for my dates"** → next page (1.3 — Curated Shortlist), with `location=banani` and `dates=eid-default` pre-applied.

**On-Page Interactions:**
- Tap "Resend code" (60s cooldown)
- Tap "Use email instead" (fallback — minimal path)
- Tap "Bangla / English" language toggle (persists choice)
- Tap location picker — modal opens with neighborhood list (Gulshan, Banani, Baridhara, Dhanmondi, Uttara, Mirpur DOHS, Other Dhaka)

## Page Composition

### Single-screen flow (mobile-first, single column)

1. **Title:** "Verify your phone" (Bangla: "আপনার ফোন নম্বর যাচাই করুন")
2. **Phone input:** Country-code prefix `+880` locked · 10-digit input · format as she types (`017XX-XXXXXX`)
3. **Primary CTA:** "Send code" — disabled until 10 digits valid
4. **OTP input (after Send code):** 6-digit single field with auto-advance between digits · 60s resend countdown
5. **Default neighborhood picker:** Dropdown — defaults to "Banani" (from landing-page location grant) or first option if location was denied · label reads "We'll show you providers in and near this area"
6. **Name input (single field):** "What should providers call you?" — defaults to first name from OTP profile if available
7. **Consent line (compact):** "By continuing you agree to PetCare's terms and Animal Welfare Act compliance posture. Your phone is verified; we never share it with providers until a booking is confirmed."
8. **Primary CTA (post-OTP):** "See providers for my dates"

## State Variations

| State | Trigger | Behavior |
|---|---|---|
| **Phone-entry default** | Page load | Phone input empty; CTA disabled |
| **OTP-sent** | Tap "Send code" | OTP input visible · phone field read-only · 60s resend countdown · auto-read SMS on Android where supported |
| **OTP-error (wrong code)** | Submit invalid OTP | Red border on OTP field · inline error "Code didn't match. Try again." · no cooldown penalty |
| **OTP-resend available** | 60s elapsed | "Resend code" link becomes active · count resets |
| **OTP-success** | Code verified | Phone field shows green check · CTA "See providers for my dates" enabled |
| **Connectivity-fail** | SMS gateway timeout | Inline error with "SMS may take 30–60s in low-signal areas" hint + manual "Type the code I received" fallback |
| **Returning user (cookie)** | Page load | Skip OTP — direct to "See providers for my dates" with name + neighborhood pre-filled |
| **Expat locale (EN + browser-locale-detected non-BD)** | Page load | Phone prefix defaults to `+880` anyway (this is a Bangladesh product); language toggle defaults to English |
| **Load-shedding window** (Brief §5 risk #14) | Detected via slow response | Show "Connection is slow — your code may take a moment" · does not block |

---

## What This Page Must NOT Do

- **No NID / address / document upload at this step** — Brief §6 minimum-viable-identity is phone OTP + name. Document upload is for providers, not owners, and even for providers it's a Tier-A/Tier-B onboarding artifact, not a sign-in step.
- **No password creation** — phone-OTP is the only auth method in v1 (Brief §6 platform-is-not-anonymous, phone OTP as minimum).
- **No marketing pop-ups** — no "Get our newsletter" or "Download the app" (no native app in v1).
- **No profile-completion prompts beyond name + neighborhood** — the first booking is the place to capture care history (FR-6), not the sign-in flow.

## On-Page State Machine (Storyboard)

```
[State 1] Phone-entry default
   ↓ (enter 10 digits · tap "Send code")
[State 2] OTP-sent
   ├── (enter 6 digits correctly) → [State 4] OTP-success
   ├── (enter 6 digits wrong)    → [State 3] OTP-error
   └── (60s elapses)             → "Resend code" link active

[State 3] OTP-error
   ↓ (re-enter or resend)
   → back to [State 2]

[State 4] OTP-success
   ↓ (tap "See providers for my dates")
   → next page (1.3 — Curated Shortlist)

[State 5] Returning user (cookie)
   ↓ (auto-confirm name + neighborhood)
   → next page (1.3 — Curated Shortlist)
```

---

## Edge / Error Paths (handle gracefully, don't break the linear flow)

- **OTP doesn't arrive after 2 minutes:** Inline error + "Tap to resend" — keeps user on page, no forced back-navigation
- **Location permission denied:** Manual picker open · defaults to "Banani" (her known neighborhood) · Bibi can change before tapping through
- **Browser doesn't support auto-read SMS:** Manual 6-digit input always available · no dependency on Android autofill
- **Bangla-input mode:** OTP field accepts both Bangla-script and Latin digits · auto-detects
