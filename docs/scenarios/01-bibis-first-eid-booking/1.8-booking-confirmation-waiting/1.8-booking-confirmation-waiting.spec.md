# 1.8 · Spec — Booking Confirmation State (Waiting on Provider)

> The post-submit confirmation. State-machine visibility is the structural answer to Bibi Fear #3. Every step has a visible state.

## URL & Routing

- **Route:** `/bookings/[bookingId]` · SSR for SEO and link-shareability · deep-linkable
- **Polling:** 30s interval for provider-confirm state changes · WebSocket fallback where supported
- **Push:** subscribe to booking channel on mount · unsubscribe on unmount

## Design Sections

**D1. Back nav** — returns to dashboard · preserves ability to return to this booking via dashboard card

**D2. Success hero** — large checkmark in `{success-soft}` background · h1 headline + sub copy · centered

**D3. Booking summary card** — `{card.muted}` · compact list · tabular-nums · Booking ID readable for support

**D4. Status timeline** — vertical step list · 6 steps · each step: dot (filled vs pending) + label + meta
- Current step: forest-green filled circle · bold label · expanded meta
- Pending steps: muted dot · muted-fg label · summary meta
- Connector lines between dots · 1px muted

**D5. Confirmation-window info callout** — `{info-soft}` background · p-4 · explicit about peak-period adjustment

**D6. Reassurance helper** — text-sm muted-fg

**D7. Primary "Done" CTA** — returns to dashboard · booking visible as card on dashboard

**D8. Secondary "Cancel this request"** — destructive-link variant · opens cancellation modal

**D9. Footer reassurance line** — "Your request is the first thing Rashid sees..." — addresses Bibi Fear #3 directly

## On-Page State Machine

States preserved. Spec adds:
- **State 1 (just submitted):** Step 1 active in timeline · 30s polling starts · push-notification subscription active
- **State 2 (provider confirmed):** WebSocket fires `booking.confirmed` event · polling stops · update timeline (Steps 1-3 active) · CTA changes to "View booking" · (sub-routes to in-stay prep, next scenario)
- **State 3 (provider declined):** `booking.declined` event · decline reason chip appears (FR-24) · CTA → "Find another provider" → 1.3 with filters preserved · booking state = declined in DB
- **State 4 (hold released, timeout):** timeline collapses · friendly empty state · CTA → 1.3
- **State 5 (cancellation modal):** `<dialog>` open · confirm-cancel releases hold and routes
- **State 6 (provider-declined-with-care-context):** if decline reason = "capacity" or "pet-safety concern", show extra copy "(Provider chose to decline because…)" · preserves brand-voice (informational, not blamey)
- **Capacity-just-changed:** rare · polling diff · re-confirmation prompt to Bibi

## Accessibility

- Hero: `<section role="status" aria-labelledby="success-h1">` · auto-focus on mount so SR announces success
- Timeline: `<ol>` native · each step `<li>` with `aria-current="step"` on active · `<time>` elements for timestamps
- Polling: silent · no `aria-live` updates on background data · updates announce only on state change (confirmed/declined/expired)
- Cancel link: confirms dialog opening with SR-announced title
- Decline reason chip: `aria-describedby` connects to full reason text
- Helper copy: `role="note"` for screen reader context
- Color contrast: forest check on cream-50 = sufficient AA ✓
