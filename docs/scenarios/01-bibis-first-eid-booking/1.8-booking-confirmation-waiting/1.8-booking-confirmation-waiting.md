# 1.8 — Booking Confirmation State (Waiting on Provider)

## Page Metadata

| Property | Value |
|---|---|
| **Scenario** | 01 — Bibi's First Eid Booking with Tito |
| **Page Number** | 1.8 |
| **Platform** | Mobile (PWA, mid-range Android) |

## Overview

**Page Purpose:** Confirm to Bibi that her request was sent, show the confirmation-window countdown, and let her step away — without anxiety about what's happening on the other side.

**Entry Context:** Bibi just tapped "Submit booking request" on 1.7 and the payment gateway authorized the hold. This page is the post-submit confirmation.

**Exit Action:** Tap **"Done"** → returns to Owner dashboard. *(Alternatively, Bibi can leave the app; she'll get a push notification when Rashid confirms or declines.)*

**On-Page Interactions:**
- Tap "Done" — primary CTA · returns to dashboard
- Tap "Message provider" — disabled state ("Chat opens once your booking is confirmed")
- Tap "Cancel this request" — secondary · opens cancellation modal

- **Hope:** The request is sent; she can step away and trust PetCare to surface the next state change
- **Worry:** She's left wondering whether Rashid saw the request; whether the hold is real; whether she should WhatsApp him "just in case"

- **Checkmark icon** (green)

## State Variations

| State | Trigger | Behavior |
|---|---|---|
| **Default (just submitted)** | Page load | Success hero · timeline with current step highlighted |
| **Provider-confirmed** | Push notification + dashboard badge | Confetti-free success toast · "Rashid confirmed" · routes to in-stay prep (next scenario hook) |
| **Provider-declined** | Push notification | Decline reason surfaced (FR-24) · "Find another provider" CTA returns to 1.3 with filters preserved |
| **Confirmation-window-expiring** | 1 hour before timeout | Banner: "Rashid has 1 hour to respond · we'll release the hold if he doesn't" |
| **Confirmation-window-expired** | Timeout | Hold released · friendly empty-state · "Find another provider" CTA |
| **Capacity-just-changed** | Provider toggles availability during the window | (rare) · re-confirmation request to Bibi |
| **User-tapped-cancel** | Tap "Cancel this request" | Cancellation modal · hold released · returns to dashboard |

---

## What This Page Must NOT Do

- **No "WhatsApp Rashid to follow up" suggestion** — this would defeat the entire platform value
- **No urgency-bait** — no "Rashid is a popular provider, he might not respond!"; the confirmation-window language is informational
- **No upsells** — no "While you wait, see other providers" (would undercut the curated-trust promise)
- **No forced re-confirmation** — what Bibi submitted is what the provider sees
- **No capture** — payment is authorized but not captured; capture happens on provider confirmation

## On-Page State Machine (Storyboard)

```
[State 1] Just submitted
   ├── (provider confirms)     → [State 2] Confirmed · routes to in-stay prep
   ├── (provider declines)     → [State 3] Declined · "Find another" returns to 1.3
   ├── (window expires)        → [State 4] Hold released
   └── (user taps Cancel)       → [State 5] Cancellation modal

[State 2] Confirmed
   ↓ (tap "Done")
   → dashboard · booking now visible in active bookings

[State 3] Declined
   ↓ (tap "Find another provider")
   → 1.3 Curated Shortlist with filters preserved

[State 4] Hold released
   ↓ (tap "Find another provider")
   → 1.3 Curated Shortlist

[State 5] Cancellation modal
   ↓ (confirm cancel)
   → dashboard · hold released
```
