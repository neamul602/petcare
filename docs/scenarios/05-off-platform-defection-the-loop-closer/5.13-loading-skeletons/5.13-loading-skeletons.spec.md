# 5.13 · Spec — Loading / Skeleton States (Cross-Cutting)

> Skeleton states preserve layout shape during data loading — never spinner-only. Initial page payload under 500 KB on 4G (Brief §3 performance envelope). Brand voice: "Loading..." (never "Please wait...").

## URL & Routing

- **Routes:** all loading states appear inline on the relevant page (no dedicated route)
- **Auth gate:** varies per loading state
- **Performance:** initial payload < 500 KB · time-to-interactive < 3s on 4G

## On-Page State Machine

- **State 1 (initial-load):** Skeleton visible · "Loading..." · back disabled · estimated-time hint
- **State 2 (data-arrived):** Skeleton fades · real content slides in · helper text disappears
- **State 3 (slow-connection):** Skeleton extended · "⏱ Connection slow · estimated 8s on 4G" · helper updated
- **State 4 (data-failed):** Skeleton replaces with error state · routes to 5.11
- **State 5 (cached-data-shown):** Cached content visible · "Showing cached results from {time}" · sync indicator

## Accessibility

- Header: `<header>` semantic · loading state `role="status" aria-live="polite"`
- Skeleton: `aria-busy="true"` · `aria-label="Loading"`
- Helper text: `aria-live="polite"` announces loading progress
- Estimated time: `aria-label="Estimated {N} seconds on 4G"`
- Slow connection: `role="status"` announces estimated time
- Skeleton shapes: not announced individually (decorative)
- All non-skeleton CTAs disabled during load · `aria-disabled="true"`

## What This Page Must NOT Do

- No spinner-only states (skeleton always preserves layout shape)
- No "Please wait..." language (brand voice: "Loading...")
- No unstyled skeletons (same height as real content)
- No blocking UI > 3s without estimated-time hint
- No skipping skeleton on slow connections (cached content shown after skeleton)
- No revealing skeleton structure to screen readers (decorative)
- No urgency-bait ("Loading quickly to get you there!")
