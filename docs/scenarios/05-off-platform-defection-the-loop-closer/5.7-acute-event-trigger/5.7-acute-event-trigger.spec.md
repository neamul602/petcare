# 5.7 · Spec — Acute-Event Trigger Surface (Provider)

> Rashid initiates the runbook when something goes wrong — **the provider-side start of the R-10 launch-blocking surface.** One-tap trigger with predefined categories; routes to 4.2 Runbook view with timeline starting. **FR-22 enforced.**

## URL & Routing

- **Route:** `/provider/stays/:bookingId/report-event` · deep-linkable from in-stay management (3.5) and from emergency banner
- **Auth gate:** `provider` role · must be assigned to the referenced booking
- **Polling:** static once submitted (route to 4.2 with timeline starting)

## On-Page State Machine

- **State 1 (default — current):** All sections shown · Confirm disabled · category + description required
- **State 2 (valid-form):** Confirm enabled · opens confirm modal
- **State 3 (confirm-modal-open):** "This will start the Runbook · Admin + owner notified" · Confirm CTA inside modal
- **State 4 (submit-pending):** Confirm disabled · spinner · "Starting the runbook..."
- **State 5 (submit-success):** Routes to 4.2 Runbook view with timeline starting · Step 1 (Confirm trigger) already checked
- **State 6 (submit-error):** "Could not start the runbook · try again or contact Ayaat directly +880-XXX-XXXX"
- **State 7 (cancel-confirm):** "Are you sure? If the pet needs urgent care, please call the vet directly"

## Accessibility

- Header: `<header>` semantic · pet context `aria-live="polite"` announces booking context
- Runbook notice: `role="status" aria-live="polite"` announces runbook start
- Category: `<fieldset>` with `<legend>` · radio group · arrow-key navigable
- Description: `<label for>` · `aria-required="true"` · char-count `aria-describedby`
- Severity: `<fieldset>` with `<legend>` · radio group
- Confirm CTA: `aria-disabled="true"` until valid · `aria-describedby` explains
- Confirm modal: `role="alertdialog"` · Confirm CTA primary
- All CTAs ≥48px tap target

## What This Page Must NOT Do

- No triggering without category (required)
- No triggering without description (required, min 20 chars)
- No improvisation prompts — categories are predefined
- No auto-resolution — every entry is human-authored
- No hiding severity self-assessment (admin needs the signal)
- No penalty if elapsed > 5min (soft reminder, no blame)
- No comparison to other acute events
