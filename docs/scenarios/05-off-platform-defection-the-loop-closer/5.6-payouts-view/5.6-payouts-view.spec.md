# 5.6 · Spec — Payouts + Earnings View (Provider)

> Rashid's payout state per booking — predictable cadence + Fit-deepening effect visible on profile views. **FR-29/FR-31 enforced:** payout is the deterministic output, not a surprise.

## URL & Routing

- **Route:** `/provider/payouts` (this view) + `/provider/payouts/:bookingId` (drill-down, out of scope)
- **Auth gate:** `provider` role
- **Polling:** every 6hr for payout-state updates · push subscription on `payouts.provider.{userId}` channel

## On-Page State Machine

- **State 1 (default — current):** Summary + table + profile views + re-engagement visible
- **State 2 (frozen-payouts-present):** Frozen notice shown · cross-link to 5.3
- **State 3 (profile-views-trending-up):** Trend indicator green · "Fit deepening"
- **State 4 (profile-views-trending-down):** Trend indicator warning · "Profile views down · consider adding photos"
- **State 5 (re-engagement-available):** Re-engagement offer visible · CTA enabled
- **State 6 (re-engagement-sent):** Confirmation · "Re-engagement nudges sent to {N} past owners" · log

## Accessibility

- Header: `<header>` semantic · summary `<dl>` semantic
- Summary cards: `<section>` semantic · tabular
- Payout table: `<table>` semantic · `<thead>`/`<tbody>`/`<th scope>` · sortable
- Frozen notice: `role="status" aria-live="polite"` announces pending disputes
- Profile views: `<section>` · `aria-describedby` connects trend to narrative
- Re-engagement offer: `<section>` semantic · CTA keyboard-accessible
- All CTAs ≥48px tap target

## What This Page Must NOT Do

- No payment-modification authority (read-only view)
- No revealing other providers' payouts
- No pressure CTAs ("Re-engage past owners before they book elsewhere!")
- No comparison to other providers' profile views
- No auto-sending re-engagement nudges (provider-initiated)
- No showing payout before completion (only after dispute window OR admin release)
