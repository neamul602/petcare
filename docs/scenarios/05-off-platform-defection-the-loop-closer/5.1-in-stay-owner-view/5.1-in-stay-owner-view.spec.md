# 5.1 · Spec — In-Stay View (Owner)

> The structural answer to Bibi's Radio-Silence fear. Daily updates, chat, vet directory, and issue-report CTA — silence is structurally impossible because the surface makes it visible-by-default.

## URL & Routing

- **Route:** `/owner/stays/:bookingId/in-stay` · deep-linkable from notification, push notification, and care history view
- **Auth gate:** `owner` role · must own the referenced booking
- **Polling:** every 60s for new daily updates · push subscription on `in-stay.{bookingId}` channel
- **Offline:** vet-clinic directory cached for last-viewed booking · available without network

## Design Sections

**D1. Header** — back to stays · "{pet} at {provider} · Day {N} of {M}" · menu trigger

**D2. Status card** — `{card.elevated}` · current state · provider · last update · next-update-due · conditional "update pending" badge

**D3. Quick-action row** — `{sticky-action-bar}` · 3 actions: Open chat · Vet directory · Report an issue

**D4. Daily updates feed** — `{card.muted}` · chronological · photo + structured note per entry · verified-by-owner indicator

**D5. Vet-clinic directory** — `{card.elevated}` · pinned · offline-cached · primary + alternatives · open hours

**D6. Actions footer** — "Mark complete" CTA · visible only on last day

## On-Page State Machine

- **State 1 (in-stay — current):** Daily updates feed populated · chat active · vet directory pinned · "Mark complete" hidden
- **State 2 (in-stay-last-day):** Last-day banner visible · "Mark complete" CTA enabled · confirmation modal opens
- **State 3 (update-pending):** "⏳ Today's update pending" badge · soft expectation language ("provider typically posts by {time}") · no blame
- **State 4 (issue-reported):** "Report an issue" CTA disabled · "Report under investigation" indicator · routes to 5.3 status
- **State 5 (acute-event-active):** Red banner · "Acute event: {event}" · CTA routes to 4.2 view (provider-side runbook is Ayaat's)
- **State 6 (mark-complete-confirm):** Modal · "Mark Tito's stay complete? This enables the review form (1+ photo required)" · confirms
- **State 7 (offline-mode):** Vet directory from cache · updates feed shows last cached · "Connection slow · showing cached from {time}"

## Accessibility

- Header: `<header>` semantic · status `aria-live="polite"` announces day-progress
- Status card: `<section>` semantic · `aria-label="In stay, day 4 of 9"`
- Quick-action bar: `<nav>` semantic · buttons keyboard-navigable
- Daily feed: `<ol>` semantic · reverse-chronological · new entries announce
- Entry photos: `<img alt="{provider-description}">` · tap to enlarge · modal `role="dialog"`
- Vet directory: `<ul>` semantic · each entry `<li>` with phone as `tel:` link
- Mark-complete CTA: `aria-disabled="true"` until last-day · `aria-describedby` explains
- All CTAs ≥48px tap target (mobile)

## What This Page Must NOT Do

- No hiding the last-update timestamp (always visible)
- No blame on provider if update late (soft expectation, never shame)
- No surfacing dispute/review inputs on this page (5.3 + 5.4 only)
- No revealing provider's other bookings
- No removing old updates (full history preserved)
- No auto-marking complete (Ayaat decides)
