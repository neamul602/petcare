# 2.1 · Spec — Pet Care History View

> The visible proof of the moat. Tito's accumulated care history exists *because* PetCare persisted it. The "Book again with Rashid" CTA is the structural answer to Bibi Fear #2 (care history lost in WhatsApp handoff).

## URL & Routing

- **Route:** `/pets/:petId/care-history` · SSR for link-shareability · deep-linkable from Owner dashboard
- **Entry points:** Owner dashboard recent-booking card · pet-card quick-link · direct deep-link
- **Prefetch:** recent-booking card hover/intersection triggers care-history query prefetch

## Design Sections

**D1. Back nav** — returns to dashboard · preserves dashboard context

**D2. Pet header card** — `{card.muted}` · rounded-lg · 4-col layout (thumb | name | meta | Edit link)
- Thumbnail: 1:1 thumb · 8-grid baseline · rounded-md
- Name + breed/age/weight stacked · tabular numerals
- "Diabetic" condition chip inline (DESIGN.md `badge.variants.warning` repurposed for medical flag)

**D3. Quick-stats row** — `text-sm text-muted-foreground tabular` · one line · dot-separated

**D4. Care-history summary** — `{card.muted}` · 6 collapsible sections (Active conditions · Active medications · Diet · Allergies · Anxiety triggers · Vet contact)
- Each section: section header (`text-sm font-semibold`) + bullet list (`text-sm text-foreground/80`)
- Sections collapse/expand · default expanded · state persists per visit
- "Vet contact" section is always expanded (Bibi Fear #1 mitigation — vet reachable in acute event)

**D5. Recent bookings (chronological)** — `{card.elevated}` per booking · most-recent first
- Header: stay title (e.g. "Eid stay with Rashid") + dates + Booking State chip (`{booking-state.completed}`)
- Photo grid: 1:1 thumbs · 4-up · 16-grid gap
- Review snippet: editorial serif (`{typography.editorial}`) · truncated to 2 lines + "…" + "Read full review" link
- Inline CTA: "Book again with Rashid" — `{button.primary, size.md}` — the page's primary action

**D6. Sticky Action Bar** — `{sticky-action-bar}` pattern (DESIGN.md) · primary "Book again with Rashid" + two link-style alternatives
- Primary CTA label reflects the most-recent provider dynamically ("Book again with Rashid", not generic)
- "Book with another proven provider" — link variant · routes to 2.2 with provider-selector open
- "Book Tito at a new stay" — link variant · routes to 1.3 Curated Shortlist with Tito pre-attached

## On-Page State Machine

- **State 1 (default, post-Eid user):** Eid stay visible · "Book again with Rashid" prominent · quick-stats show "1 booking"
- **State 2 (pre-Eid, first-time user — empty history):** Care-history sections show **placeholder copy** ("No bookings yet — Tito's first stay will appear here") · quick-stats hidden · primary CTA changes to "Find care for Tito" → routes to 1.3
- **State 3 (multi-pet household):** Pet selector at top · tapping switches active pet · care history re-renders for selected pet · sticky CTA updates primary label
- **State 4 (provider no longer available):** Rashid is paused/suspended by Admin · inline past-booking card shows "Rashid is currently not accepting bookings" warning · primary CTA shifts to "Book with another proven provider" (becomes button.primary instead of link) · "Book again with Rashid" hidden
- **State 5 (care-history-sparse, declined first booking):** Past-booking card shows "Declined" state with decline-reason chip `{badge.decline}` · CTA "Book with a different provider" · no sticky "Book again" CTA (the structural answer was declined, not absorbed)

## Accessibility

- Pet header: `<header>` semantic · pet name as `<h1>` · Edit toggle as `<button aria-label="Edit Tito's profile">`
- Care-history sections: `<details>` / `<summary>` native · state preserved across visits via localStorage
- Vet contact: phone link `<a href="tel:+880-...">` · single-tap-to-call on mobile
- Past-booking card: `<article>` semantic · CTA is the primary focusable element
- Photo grid: `<ul>` semantic · each `<li>` has descriptive `alt` text
- Booking State chip: `aria-label="Stay completed, 5-star rating"` (chip + rating combined)
- Sticky CTA: `aria-label="Book again with Rashid, Eid-week care provider"` · focus ring always visible
- State 4 (provider unavailable): `role="status"` announcement on state change for SR users
- All CTAs ≥48px tap target · spacing respects 8-grid baseline

## What This Page Must NOT Do

- No "Export your data" CTA beyond GDPR request (moat conditionality per Brief §6)
- No "Delete pet profile" CTA at top level (soft-delete via Settings only)
- No upsells ("Upgrade to PetCare+" — no subscription in v1)
- No urgency-bait ("Rashid's calendar fills up fast!")
- No blank care-history sections when history exists (every section has a value or "None known")
- No provider-rank badge if Rashid isn't Tier-A (tier-marking only on Tier-A)
