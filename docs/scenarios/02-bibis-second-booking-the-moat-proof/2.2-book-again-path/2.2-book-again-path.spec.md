# 2.2 · Spec — Book Again Path (Pre-filled Intake)

> **THE SM-15 CLIMAX PAGE.** When Bibi submits in under 4 minutes, the moat is structurally visible. Single-screen intake with all care-history fields pre-filled · Bibi adjusts only what's stay-specific.

## URL & Routing

- **Route:** `/bookings/book-again?petId=&providerId=` (deep-linkable with prefilled context)
- **Prefill source:** GET `/api/pets/:petId/care-history` · the request payload contains the full intake pre-filled server-side; client renders directly
- **Polling:** none (this is a one-shot intake screen; state-machine visibility is 1.8's job)
- **Submit:** POST `/api/bookings` with full intake payload → routes to payment-authorization step (functionally 1.7-equivalent)

## Design Sections

**D1. Back nav** — returns to 2.1 (care history) · preserves prefill context

**D2. Page title + elapsed-time indicator** — `{typography.editorial}` h1 + `{success-soft}` pill below
- Elapsed time is **live** (updates every second client-side) · `role="timer"` with `aria-live="off"` (silent update; SR doesn't read every tick)
- Color thresholds: **Under 4 min** = `{success-soft}` (calm reassurance) · **4–6 min** = muted (informational) · **Over 6 min** = same muted (no penalty, the user may have edited more)
- After submit, the indicator freezes and gets a checkmark: "Faster than your first booking ✓"

**D3. Pre-filled context card** — `{card.muted}` · summary line per axis (Provider · Pet · Dates)
- Provider line includes Tier-A badge (`{tier-a-badge}`) and demonstrated-Fit snippet ("12 diabetic small dogs handled")
- Pet line includes medical flag (Diabetes) and routine (Insulin BID)
- Dates line shows defaults with "change" link → opens date picker

**D4. Care-history sections** (collapsible) — 5 sections, each:
- Section header with toggle: "✓ Use saved (value)" or override toggle
- When toggle ON: shows saved value, no input visible, no edit on tap (display-only)
- When toggle OFF: shows input/textarea for override
- "Use saved" toggles use `{toggle.primary-soft}` when on (visual consistency with the "Use saved" pattern from 1.6)
- Edited sections show inline "edited" chip · `{badge.neutral}` · indicates divergence from saved value

**D5. New note for this stay** — single free-text area · placeholder copy: "Anything specific for this stay — favorite toys, anxiety triggers, the blanket Tito sleeps with"
- No pre-fill (this is by definition stay-specific)
- Auto-saves on blur to local draft

**D6. Pickup time** — single time-picker field · defaults to last stay's pickup time

**D7. Sticky Action Bar** — `{sticky-action-bar}` · price-summary block + primary "Submit booking request" + "Save as draft" link
- Price summary shows **authorization hold** language (not "charge") — same `{info-soft}` callout discipline as 1.7
- Primary CTA: `{button.primary, size.lg}` · full-width · "Submit booking request →"
- Secondary: "Save as draft" · `{button.variant.link}` · routes to Owner dashboard with toast
- Submit disabled until minimum required fields validated (dates, at least one of food/medication override or use-saved confirmed)

## On-Page State Machine

- **State 1 (default pre-filled):** All care-history fields show "Use saved (value)" toggles ON · override inputs hidden · dates editable
- **State 2 (different-provider path):** Came from "Book with another proven provider" on 2.1 · provider-selector step at top · shortlist filtered to providers who have handled Tito's case (Diabetes + small breed) · selecting a provider returns to State 1 with that provider's data
- **State 3 (capacity-conflict, Rashid unavailable):** Backend returns 409 on prefill fetch · page renders with warning banner · "Rashid unavailable for these dates — see alternatives" · provider-selector opens · price recalculates
- **State 4 (pre-filled but edited):** User changed any field · "Edited from saved care history" chip appears on that section · edited value persists · submit writes edited value back to care history on success (preserves care-history accumulation principle)
- **State 5 (submit-success):** Submitted · routes to 1.7-equivalent payment authorization · elapsed timer freezes with checkmark · toast: "Booking request sent to Rashid · {N} min {S} sec"

## Accessibility

- Page header: `<header>` semantic · h1 is the page title
- Elapsed timer: `role="timer"` with `aria-live="off"` (silent update — does not interrupt SR) · `aria-label="Elapsed time: 2 minutes 15 seconds, faster than your first booking"`
- Pre-filled context: `<section>` with `<dl>` semantic · each row is `<dt>`/`<dd>`
- Care-history sections: `<details>` / `<summary>` native · expanded state preserved across re-renders via localStorage
- Use-saved toggles: `role="switch" aria-checked` reflects state · keyboard operable (Space)
- Override inputs: visible only when toggle OFF · `aria-hidden="true"` when toggle ON
- Edited chip: `aria-label="Edited from saved value"` · not just visual
- Authorization-hold note: `role="note"` for SR context
- Primary CTA: `aria-label="Submit booking request, total authorization hold BDT 6,600"` · full context on focus
- Submit-success state: `<section role="status" aria-live="polite">` announces completion
- All CTAs ≥48px tap target · sticky bar respects safe-area inset

## What This Page Must NOT Do

- No blank fields when care history exists — every section has a value or "None known"
- No re-typing of the insulin curve — pre-filled, editable inline
- No "Start over" CTA at the top — "Start over" lives in overflow menu only
- No pre-charged upsells — services from last stay are pre-selected but not pre-charged
- No urgency-bait — no "Submit now to lock in these dates!" (confirmation-window discipline is 1.8's job)
- No gamification — timer is for **user reassurance**, not competitive ranking
- No fake pre-fill — if care history is genuinely empty, render placeholder copy, not placeholder data
