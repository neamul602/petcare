## Overview

**Page Purpose:** Pre-fill the booking configuration from Tito's accumulated care history in a single screen, let Bibi adjust only what's stay-specific (dates, any new notes), and submit — the **SM-15 climax** is reached when the entire flow takes under 4 minutes.

**Entry Context:** Bibi tapped "Book again with Rashid" on 2.1 (or "Book with another provider"). The page is a streamlined single-screen intake with all care-history fields pre-filled.

**Exit Action:** Tap **"Submit booking request"** → routing to a payment-authorization step (functionally identical to 1.7 but visually streamlined since the intake is already validated).

**On-Page Interactions:**
- Tap any pre-filled field — opens inline editor
- Tap "Add a new note for this stay" — expands free-text input
- Tap date range — opens date picker
- Tap "Submit booking request" — primary CTA, sticky

## State Variations

| State | Trigger | Behavior |
|---|---|---|
| **Default pre-filled** | Page load | All care-history fields pre-filled · dates editable |
| **Different-provider path** | Came from "Book with another provider" | Provider-selector step at top · shortlist of proven providers |
| **Capacity-conflict (Rashid unavailable)** | Provider's capacity changed | "Rashid unavailable for these dates — see alternatives" · provider-selector |
| **Pre-filled-but-edited** | User changed any field | "Edited from saved care history" indicator · still saves back to care history |
| **Submit-success** | Submitted | Routes to payment authorization (1.7-equivalent) · total time tracked |

---

## What This Page Must NOT Do

- **No blank fields** — every care-history field has a value from Tito's profile
- **No re-typing of the insulin curve** — pre-filled, editable inline
- **No "Start over" CTA at the top** — the pre-fill is the point; "Start over" is in overflow menu only
- **No upsells** — services from last stay are pre-selected but not pre-charged
- **No urgency-bait** — no "Submit now to lock in these dates!" (the confirmation-window discipline applies the same as 1.8)

## The SM-15 Climax Feedback Loop

A **non-intrusive timer** in the corner of the sticky CTA shows elapsed time since the page loaded. The target is **under 4 minutes**. When the user submits:

- **Under 4 min:** Green check · "Faster than your first booking ✓" · success toast
- **4–6 min:** Neutral · "Your second booking is faster than your first"
- **Over 6 min:** No penalty · just informational — the user may have edited more

This timer is for **user reassurance**, not gamification. It is the visible proof that staying on PetCare is structurally faster than WhatsApp.
