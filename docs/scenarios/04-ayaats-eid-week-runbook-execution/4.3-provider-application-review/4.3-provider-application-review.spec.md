# 4.3 · Spec — Provider Application Review

> Tier-B application vetting — identity, address, references, capacity, vaccination-proof. **Brief §5 risk #6 mitigation:** transparent criteria, bias-aware language, right-of-appeal link.

## URL & Routing

- **Route:** `/admin/applications/:applicationId` · deep-linkable from queue dashboard's applications section
- **Auth gate:** `admin` role
- **SLA:** applications have a 7-day SLA · countdown shown in header

## Design Sections

**D1. Header** — back to queue · applicant name · tier · neighborhood · SLA countdown

**D2. Vetting artifacts** — `{card.muted}` · 6 rows · checkmarks for verified · pending indicators for awaiting

**D3. Vetting criteria checklist** — `{card.muted}` · granular sub-criteria · checkbox state per item

**D4. Bias-audit policy block** — `{info-soft}` · inline disclosure · right-of-appeal link

**D5. Sticky Action Bar** — `{sticky-action-bar}` · 3 actions: Request more info · Decline (with reason) · Approve

## On-Page State Machine

- **State 1 (new-application):** SLA countdown started · artifacts partially populated · criteria partially checked
- **State 2 (awaiting-info):** Application paused · applicant notified · "awaiting {N} items" indicator
- **State 3 (criteria-complete):** All criteria checked · Approve enabled
- **State 4 (Tier-A-invitation-outreach):** Different flow · admin's outbound outreach track (not Tier-B application) · distinct UI path
- **State 5 (bias-audit-periodic):** Quarterly audit banner · "All approval decisions in {quarter} shown for review"
- **State 6 (declined):** Decline reason logged · applicant notified with appeal mechanism · application archived
- **State 7 (approved):** Moves to Tier-B onboarding flow · ceiling math updates on dashboard banner

## Accessibility

- Header: `<header>` semantic · SLA `aria-label="{N} days remaining"`
- Vetting artifacts: `<dl>` semantic · each row is `<dt>`/`<dd>`
- Criteria checklist: native `<fieldset>` with `<legend>` · `aria-checked` reflects state
- Bias-audit banner: `role="note"` · appeal link is keyboard-accessible
- Decline modal: `role="alertdialog"` · reason field `aria-required="true"`
- Approve modal: `role="dialog"` · optional notes field
- All CTAs ≥48px tap target

## What This Page Must NOT Do

- No approving without all criteria checked
- No declining without reason (taxonomy enforced)
- No hiding approval-decision rationale from applicant (Brief §5)
- No comparison to other applicants ("Sadia vs. other Tier-B candidates")
- No "fast-track" approval paths in v1
