# 4.9 · Spec — Post-Mortem Practice Log

> Closes every acute event with a documented post-mortem — the entry feeds back into the runbook so platform response improves over time. **SM-19 climax:** post-mortem closure anchored. **Ayaat Want #1 (runbook improvement loop):** the closing surface that closes the loop.

## URL & Routing

- **Route:** `/admin/postmortems` (library) + `/admin/postmortems/:eventId` (form, deep-linkable from 4.2 Step 7) + `/admin/postmortems/versions` (runbook version history)
- **Auth gate:** `admin` role
- **Polling:** every 5min for new post-mortem reminders · push subscription on `postmortem.due` channel

## Design Sections (Library View)

**D1. Header** — back to queue · library summary line (documented count · due count · runbook version active)

**D2. Reminder banner** — `{warning-soft}` · conditional · only when post-mortem is due · CTA to form

**D3. Filter + sort row** — `{filter-chip}` · 6 options · sort selector

**D4. Pattern detection** — `{info-soft}` · aggregated insight · "X of N events involved Y" · apply-to-version CTA

**D5. Library cards** — `{card.muted}` · event ID · type · runbook version · worked/didn't/next · lessons-shared · apply CTA

## Design Sections (Form View)

**D6. Event header** — `{card.muted}` · read-only · all event context · runbook version comparison

**D7. Post-mortem form** — `{card.elevated}` · 4 sections: summary, what worked, what didn't, what to change · lessons-shared toggle · save + apply CTAs

## On-Page State Machine

- **State 1 (library — current):** Cards visible · pattern detection at top · filters + sort
- **State 2 (reminder-active):** Reminder banner visible · CTA routes to form for that specific event
- **State 3 (filter-applied):** Cards re-render to match filter · count updates
- **State 4 (pattern-applied):** Apply CTA creates a runbook-version proposal · banner: "Version v4 proposed · review in versions"
- **State 5 (form-new):** Empty form · save disabled until required fields · apply CTA disabled
- **State 6 (form-pre-populated):** Steps pre-checked from runbook history · Ayaat edits · save enabled
- **State 7 (form-saved):** Saved · cross-link to library · entry visible at top
- **State 8 (form-applied-to-version):** "Applied to runbook v4 · review in versions"
- **State 9 (runbook-version-history):** Timeline of versions · diff between versions · "what changed when"

## Accessibility

- Header: `<header>` semantic · summary `<dl>` semantic
- Reminder banner: `role="status" aria-live="polite"` · announces due post-mortem
- Pattern detection: `role="note"` · apply CTA keyboard-accessible
- Library cards: `<article>` semantic · CTA primary focusable
- Form fields: `<label for>` per field · required `aria-required="true"`
- Lessons-shared radio: `<fieldset>` with `<legend>` · arrow-key navigable
- Save CTA: `aria-disabled="true"` until valid · `aria-describedby` explains why
- Apply CTA: `aria-describedby="version-preview"` · previews diff
- Version history: `<ol>` semantic · diff with `<ins>`/`<del>` semantic markup
- All CTAs ≥48px tap target

## What This Page Must NOT Do

- No skipping required fields (event summary + next-version changes required)
- No auto-saving partial entries (full or nothing)
- No sharing lessons without explicit radio selection
- No comparison to other platform post-mortems ("post-mortems resolve faster elsewhere")
- No pressure CTA on the 48hr window (soft reminder, no penalty)
- No public visibility of post-mortems (admin + provider + owner only)
