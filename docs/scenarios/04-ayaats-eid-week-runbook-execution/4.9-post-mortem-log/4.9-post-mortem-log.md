# 4.9 — Post-Mortem Practice Log

## Overview

**Page Purpose:** Closes every acute event with a documented post-mortem entry — the entry feeds back into the runbook so platform response improves over time. SM-19 climax.

**Exit Action:** Save post-mortem · next-version-of-runbook CTA.

## Page Composition

### Post-mortem form
- Event summary
- What worked (runbook steps that fired correctly)
- What didn't (steps that needed improvisation)
- What to change in the next version of the runbook
- Lessons-learned · shared with all providers (optional)

### Library of past post-mortems
- Filter by event type · outcome · provider
- Pattern detection · "5 of 12 acute events involved diabetic small dogs · consider Tier-A diabetic-care specialization?"

### Feed-back into runbook
- "Apply this update to the runbook v[X+1]" CTA
- Version-controlled runbook (admin can diff versions)

## State Variations

- **Recent-event-no-postmortem**: Banner "Acute event from 2 days ago · post-mortem due"
- **Runbook-version-history**: Timeline of runbook versions · what changed when
