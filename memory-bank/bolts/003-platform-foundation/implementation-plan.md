## Implementation Plan: platform-foundation, second bolt (bolt 003 of 25)

Approved under the owner's standing instruction of 2026-10-29 (use the recommendation, do not ask between steps).

### Objective

Finish the foundation: make the app installable and tolerant of a weak connection, add the shared loading, empty, error and offline patterns, put automated performance and accessibility checks in place, and create the labelled training seed with a reset-and-load command.

### Stories and requirements

1. **FND-04 PWA, offline and shared states** (must): FR-46, DR-18, NFR-15; page specs 5.11, 5.12, 5.13
2. **FND-06 Performance and accessibility checks** (should): NFR-1, NFR-2, NFR-15, DR-19
3. **FND-07 Training scenario seed** (must): TR-7, TR-8, DR-15

### What will change

- **Installable PWA:** web manifest with icons, a Workbox service worker generated at build time (precache of the app's styles, scripts and the Latin and Bengali fonts; pages cached as they are visited), an offline fallback page, and registration in production builds only.
- **Offline behaviour:** a connectivity banner shows "Offline..." text in the visitor's language when the connection drops; pages already visited still open from the cache; form fields marked for persistence keep what was typed on the device and restore it later.
- **Shared states:** reusable Loading (skeleton), Empty and Error components, with the error variants from page spec 5.11 (network, server, not found, permission, offline), each with a clear next action and no invented content. Shown in the development kit gallery.
- **Performance:** fonts limited to the Latin and Bengali subsets so the service worker does not precache unused scripts; automated checks load owner and provider screens under a throttled 4G profile and fail if the transferred payload reaches 500 KB or the page is not interactive within 3 s (measured as a proxy; a full Lighthouse report is produced at workbook Step 32).
- **Accessibility:** an automated axe scan of all 30 routes in both languages for WCAG 2.1 AA, a keyboard check (skip link first, visible focus), and a spacing check that adjacent touch targets are at least 8 px apart. The tab bar gets 8 px gaps to meet this.
- **Training seed:** labelled JSON seed files (neighbourhoods and vet clinics per neighbourhood; owner Bibi and pet Tito; provider Rashid; admin Ayaat; three further approved providers across both tiers; one pending Tier-B application), a validator that refuses any review, rating, booking count or testimonial, and `npm run seed`, which recreates the database from migrations, loads the data and resets the Dummy services if they are running.

- Unit tests for the seed validator and loader; `package.json` scripts `build:pwa`, `seed`, `test:e2e`

### APIs

None added. The seed command talks to PostgreSQL and, if running, to the Dummy services' `reset-all` training endpoint.

### Decisions (made by recommendation)

1. **Service worker:** generated by Workbox with pages cached network-first (3 s timeout, then cache) and static assets precached. Cached read screens (pets, care history, bookings) arrive with their own bolts and need no change here because the rule applies to every visited page.
2. **Seed scope for this bolt:** the seed files, validation and reset-and-load command are built now, and neighbourhoods and vet clinics are loaded into two small reference tables created here. Owner, pet, provider and admin records are validated now and loaded by the bolts that create their tables (004 accounts, 005 pets, 006 providers); each of those stories gets a note.
3. **Icons:** a forest-green rounded square with a cream ring-and-dot mark; no paw print (a DESIGN.md anti-reference).
4. **TTI measurement:** time until load completes plus all page islands hydrated, under CDP network (about 1.6 Mbps, 150 ms) and 4x CPU throttling. Honest proxy, documented as such.
5. **Offline form submission:** only the persistence of typed input is built here; sending a held booking when back online belongs to story BKG-03.

### How it will be tested

- Vitest: seed validation (accepts the real seed; rejects a rating, review, testimonial or booking count; requires the label), seed counts and content, loader against real PostgreSQL (reset recreates the database, reference data present, running twice gives the same result).
- Playwright (production build for PWA and performance): manifest fields and icons load; service worker registers and controls the page; a visited page opens offline with the banner; typed form input survives a reload; shared state components render in both languages; payload under 500 KB and interactive within 3 s under throttling on owner and provider home; axe finds no WCAG 2.1 AA violations on any route in Bangla and English; skip link is first and focus is visible; adjacent targets have 8 px spacing.

### Acceptance criteria

- [ ] FND-04: installable; offline banner and cached pages; typed input kept and restored; loading, empty and error patterns exist with clear next actions and no invented content
- [ ] FND-06: initial payload under 500 KB; interactive under 3 s on throttled 4G; no WCAG 2.1 AA violations; keyboard order and focus visible; 8 px spacing
- [ ] FND-07: seed loads the labelled scenario and recreates the database; no review, rating, booking count or testimonial; running it twice gives the same state

### Out of scope

Sending held bookings (BKG-03); real push (deferred); notification inbox (deferred); loaders for people, pets and providers (bolts 004-006); full Lighthouse report (Step 32).
